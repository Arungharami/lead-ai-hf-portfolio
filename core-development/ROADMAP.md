# Professional Roadmap

## Phase 1 — Complete onboarding

- [x] Confirm email
- [x] Complete profile
- [x] Follow two users and one organization
- [ ] Like two more assets so the model/dataset/Space task reaches 3/3
- [ ] Upvote one relevant paper, article, or collection
- [ ] Complete the remaining product or service discovery item

Recommended choices should align with your research interests: trustworthy AI, explainability, fraud detection, embedded ML, and intelligent decision support.

## Phase 2 — Hub foundations

- [ ] Install the `hf` CLI
- [ ] Run `hf auth whoami`
- [ ] Understand model, dataset, and Space repository types
- [ ] Learn revisions, branches, tags, commits, and pull requests on the Hub
- [ ] Learn safe token handling and repository permissions

## Phase 3 — Python SDK

- [ ] Use `HfApi` to discover models, datasets, and Spaces
- [ ] Save structured metadata to JSON
- [ ] Inspect repository cards and tags
- [ ] Download a small repository snapshot
- [ ] Understand local cache behavior

## Phase 4 — Models and inference

- [ ] Select one small model relevant to your research
- [ ] Document task, framework, license, limitations, and expected inputs
- [ ] Run a deterministic inference example
- [ ] Add error handling and input validation
- [ ] Compare at least two models using the same evaluation criteria

## Phase 5 — Dataset engineering

- [ ] Select one dataset with a clear license
- [ ] Review the dataset card
- [ ] Record schema, splits, size, missing values, and known risks
- [ ] Create a small validation script
- [ ] Document whether the dataset is appropriate for the intended model task

## Phase 6 — Space development

- [ ] Build a Gradio interface locally
- [ ] Add examples and validation
- [ ] Add a responsible-use notice
- [ ] Add a clear README with setup and limitations
- [ ] Deploy or prepare the repository for deployment to Spaces

## Phase 7 — Engineering quality

- [ ] Add unit tests
- [ ] Add Ruff linting
- [ ] Add GitHub Actions
- [ ] Use semantic commit messages
- [ ] Use a pull request template
- [ ] Track tasks with GitHub issues

## Phase 8 — Open-source contribution

- [ ] Identify a beginner-friendly issue in a Hugging Face repository
- [ ] Reproduce the issue locally
- [ ] Read contribution guidelines
- [ ] Propose a narrowly scoped fix or documentation improvement
- [ ] Add tests or clear validation evidence
- [ ] Open a focused pull request

## 30-day outcome

At the end of 30 days, the portfolio should contain one polished model review, one dataset review, one working Space, one automated test workflow, and one documented open-source contribution attempt.
